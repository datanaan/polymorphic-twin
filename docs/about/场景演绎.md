从整个演进过程的起点开始追溯，看看现在的系统——Core v1.3、Lab v0.4、Bridge v0.3、TwinObjectModel v0.3、DomainPack v0.3——在这些场景里到底能做什么、不能做什么、提供的价值是什么。

场景一：机器人开发
回溯起点
最初讨论 Koopman 数字孪生时，机器人场景被设想为“多范式模型动物园”的主场——四个骨架全部激活，自由切换。后来 Core 收敛为约束治理系统，Lab 收敛为隔离探索引擎，Bridge 补上了行动空间映射。

当前系统能做什么
训练阶段：

在仿真环境（Isaac Gym/MuJoCo）中训练控制策略时，DomainPack 声明“四足机器人接触动力学”场景的状态语义、约束卡片和安全回落策略——核心是足地接触力非负、关节力矩不超过物理极限、机身姿态不倾覆。

Lab 在隔离环境中自由尝试新的接触模型结构（杂交 Koopman 线性层与 FNO 接触场层），生成候选模型。它不接触真实机器人。它的产出只是一个 CandidateModelPackage。

Core 在 sandbox 中对 Lab 产物执行检疫和 HardGate：这个候选模型在训练域内是否满足接触力非负约束？是否持有有效的不确定性证书？通过后标记为 sandbox 权限，等待进一步升级验证。

Sim-to-Real 部署时：

这是系统价值最明显的时刻。策略从仿真部署到真实机器人时，接触动力学完全不同。仿真中学到的模型在真实硬地上可能还好，踩到软沙时立即失效。

Core 实时监控每个模型的资格状态。当足端接触从硬地切换到软沙，Koopman 模型因训练域不匹配被 HardGate 标记为 OOD，自动降权至 diagnostic_only——不再参与控制输出。FNO 接触场模型如果持有该地形的验证证书，资格提升至 production_control。

Bridge 在此时不输出“建议执行A”，而是结构化呈现：可立即执行（使用FNO模型继续行走，风险低）、有条件执行（若想使用Koopman模型，需提供软沙域校准证据）、禁止执行（不允许在FNO模型也未覆盖的完全未知地形上自主行走）。

当地形突变导致所有模型的 production_control 资格都丧失时，Core 不硬输出控制指令，而是立即执行安全回落——降低步速、稳住重心、进入安全保持姿态。

持续运行阶段：

真实机器人在野外采集的每一步数据，通过 Core 写入 TwinObject。Lab 在新数据上（脱敏后，通过 DataReleasePackage 授权）继续探索——生成反事实场景“如果踩到更软的地形会怎样”、发现新的失效模式、提交新候选模型。

如果某次摔倒事件被记录，Core 将其放入 quarantine_set。经脱敏和安全审查后释放给 Lab，Lab 分析出“在松软地形上转向过急导致侧滑”的负面结果，Core 采纳后将其纳入当前验证集和风险门槛的更新依据。

这套系统不是什么
不是运动规划器，不是强化学习训练框架，不是实时 QP 控制器。它是部署在“仿真模型”和“真实物理机器人”之间的可信治理层——不是让预测更准，而是阻止一个在它自己不知道的域里已经失效的模型继续控制机器人。

场景二：科研项目
回溯起点
最初讨论中，科研项目被列为八个目标场景之一，当时说“骨架D可能闲置”。现在看，闲置不是问题——科研场景的核心价值不取决于用了几个骨架。

当前系统能做什么
湍流/气候/复杂系统研究：

研究员用深度学习发现了湍流中的一个新模态。问题是：这是物理上真实的新现象，还是模型在 OOD 区域的虚构？

Core 的约束验证和冲突诊断流程被调用。检查传感器数据源是否正常——排除观测错误。检查已知物理约束（质量守恒、动量方程）是否满足——若新模态下质量不守恒，约束卡片返回 fail。系统不直接宣布“新发现”，而是标记为“候选新现象，待验证——当前约束适用域可能不匹配”。

研究员不是只拿到一个“是/否”的回答。Bridge 呈现的是一个结构化的知识状态：当前已知的约束覆盖了哪些、新模态违反了哪些约束（或哪些约束处于 not_applicable）、区分“模型错误”与“真实新现象”还需要什么证据——可能需要增加观测、可能需要修改约束适用域、可能需要人工审查。

Lab 在这个场景下专门生成反事实场景：“如果这个新模态是真实的，在什么条件下它应该能被复现？”然后把这些场景提交 Core 作为验证场景候选。

气候预测：

一个气候模型预测十年后某区域温度上升 2°C，置信度极高。Core 检查该模型的资格：训练数据覆盖了哪些气候态？当前排放路径是否在训练域内？模型的不确定性证书是否在十年外推域仍有效？若模型在长期外推 OOD 且无有效证书，Core 将其降权至 diagnostic_only。Bridge 输出“当前模型对十年后的预测不可靠，未知域范围是 X。可执行行动：使用保守物理约束模型（基于能量平衡）给出更宽但更可信的预测范围。”

这套系统不是什么
不是自动论文生成器，不是实验设计优化器，不是替代科学家的假设提出。它是为科研中的“发现”提供可证伪检验结构——系统不说“这是新现象”，系统说“当前已知的约束和模型无法解释这个观察，已排除传感器错误和已知模型失效，建议将其作为候选新现象进一步验证”。

场景三：数据分析（工业设备健康管理）
回溯起点
最初讨论数据分析时，说“骨架C和D可能闲置，骨架B（Koopman）是核心”。这个判断在演进中发生了变化——不是因为骨架闲置是问题，而是因为系统的价值不在“用哪个骨架”，而在“知道什么时候不能用哪个骨架”。

当前系统能做什么
风机/泵/压缩机退化监测：

振动频谱在变，温度在漂，效率在降。是正常老化，还是传感器漂移，还是真的在走向故障？

Core 持续监测 TwinObject 的 identity_confidence。当多个传感器信号与所有资格模型的残差都在缓慢增大，但每个单独偏离都未触发传统阈值报警时，Core 累积身份不确定性。当 identity_confidence 从 high 降到 medium，Core 将 lifecycle_state 迁移至 identity_uncertain。

Bridge 在这一刻输出的不是“轴承将在 X 天后失效”——那是传统 PHM 做的事。Bridge 输出的是结构化诊断选项：当前可能解释有传感器漂移（概率 X，可增加交叉验证）、真实退化（概率 Y，可发起主动探测）、外部工况变化（概率 Z，可检查运行日志）。可立即执行的是增加观测频率、执行安全保持。有条件执行的是发起主动探测（需要 ActiveProbe Certificate）。禁止执行的是“当作一切正常继续满负荷运行”。

这不是剩余寿命预测。这是在退化还没有真正改变系统身份之前，捕捉到身份连续性的最早动摇。

当预测模型被要求给出RUL时：

即使一个深度学习 RUL 模型给出“剩余寿命 72 小时，置信度 95%”，Core 不会直接释放这个输出。Core 检查：模型在退化域是否有校准数据？不确定性证书是否在晚期退化域仍有效？若均无，Bridge 输出“当前无生产级 RUL 模型。已知退化趋势存在，但剩余寿命不可知。安全边界内的最长保守运行估计为 Y 小时。建议在 Z 小时内安排检查。”

这套系统不是什么
不是替代振动分析师，不是替代 FFT 频谱分析，不是替代传统的阈值报警系统。它是部署在“正常”和“报警”之间的灰区——在传统 PHM 系统说“出问题了”之前，系统已经在说“我开始不确定它还是不是昨天的那个系统了”。

场景四：医疗研究（帕金森/阿尔茨海默）
回溯起点
医疗场景是推动“为什么引入深度网络和 Transformer”讨论的原始动机。当时说的数据复杂性、长程依赖、个体异质性——现在在三系统生态中都有了对应的治理结构。

当前系统能做什么
帕金森疾病进展建模：

一个患者的步态在六个月内逐渐改变。可穿戴设备数据、临床量表、影像数据持续进入系统。DomainPack 声明了“帕金森运动功能监测”场景的状态语义（UPDRS 评分、步态冻结指数、震颤幅度、左旋多巴等效剂量）、约束卡片（药物代谢动力学约束、运动功能不可逆性约束——即真实神经退行不可自愈）、和行动模板（增加用药频率、调整 DBS 参数、增加康复训练）。

深度学习模型预测患者三个月后 UPDRS 评分会从 28 恶化到 42。Core 检查：模型在患者当前年龄、病程、用药方案下是否有校准证据？模型是否有有效的干预有效性审查——即它是否在类似患者的用药调整数据上验证过？若均无，模型被降权。

与此同时，药物代谢动力学约束显示，按当前用药方案的半衰期和等效剂量，这种幅度的恶化不应该在三个月内发生。Core 检测到数据驱动模型预测和生理约束之间的冲突，进入冲突诊断流程。诊断结果可能是“模型处于 OOD 域——该患者在训练数据中缺乏类似年龄/病程组合的样本。建议增加观测频率，暂不基于该模型调整用药。”

Bridge 不是给医生发一条自然语言建议。它输出的是结构化选项：可立即执行的是增加观测频率、安排临床评估。有条件执行的是“若想使用模型A的预测作为参考，需提供该患者的前三个月数据作为域内校准”。禁止执行的是“基于未验证模型大幅调整左旋多巴剂量”。

身份分叉的临床事件：

患者从“震颤为主型”开始出现显著“步态冻结”。这是疾病亚型迁移，但仍可能是同一个患者的进展。Core 的 identity_confidence 下降。系统进入 identity_uncertain，但不贸然假设旧模型完全失效。Bridge 呈现行动选项：可立即执行的是在现有安全边界内继续当前用药，增加冻结发作的日志记录。有条件执行的是发起身份分叉流程——创建一个新的临床分支记录，标记 breaking invariants（震颤转向冻结）和 inherited invariants（患者仍对左旋多巴有响应）。禁止执行的是“丢弃所有历史模型，改用一套全新的预测”。

这套系统不是什么
不是诊断工具，不开药，不替代临床指南，不做影像分析。它是一个临床不确定性治理系统——在观测模糊、机制不确定、干预后果不可知的灰色区域，结构化地告诉医生“当前能信什么、不能信什么、在什么条件下可以跨越边界”。

场景五：教育培训
回溯起点
教育场景在最初的八场景压力测试中就出现过。当时说“框架可能吓退教育用户，需要教学模式 GUI”。现在有了 Bridge 的行动空间概念，教育场景可以做更有趣的事。

当前系统能做什么
动力学建模教学：

学生在双摆系统上做实验。从微幅摆动的小角度近似，逐渐增大初始角度进入混沌。DomainPack 声明了双摆的物理约束（能量守恒、连杆长度不变）。

当系统处于微幅摆动时，学生看到 Koopman 模型的资格是 production_prediction，Hamiltonian 模型也在 production，FNO 模型资格为“不适用——无需场描述”。

当初始角度增大到混沌域，Koopman 模型的资格开始下降。Core 检测到在线性提升空间中特征值谱出现新的不稳定模态。HardGate 将其降权为 diagnostic_only——不能用于长期预测，但可用于短时诊断。学生直接看到资格状态的变化，不是老师讲“Koopman 不适合强非线性”，而是约束和资格函数自己展示了边界。

学生可以故意“做坏事”——把能量守恒约束卡片从 absolute 改为 soft。Core 拒绝，因为 DomainPack 中 safety_critical 必须是 absolute。Bridge 输出“该约束的刚性不可降低。若要修改，需发起约束修订流程并重新认证 DomainPack。”这本身就是一堂关于“物理约束为什么不能随便放松”的课。

当学生故意制造一个不可能的状态（如两个连杆穿越彼此），约束验证返回 fail。Core 阻止该状态被释放，Bridge 输出“该状态违反连杆不可穿越约束——约束卡片 C3。原因：可能是初始条件设置错误。”

这套系统不是什么
不是物理仿真器，不是替代教科书，不自动评分。它是一个让数学物理概念之间的边界变得可见的实验平台——学生不是被教“这个方法不适合”，而是直接看到方法资格的边界在哪里。

场景六：新材料研发
回溯起点
新材料是八场景中唯一一个“四骨架全部有应用，无臃肿感”的场景。当时说“骨架C和D是核心，骨架A和B可能用于疲劳演化”。

当前系统能做什么
微观结构→宏观性能预测：

工程师有新配方的微观结构图像，想预测疲劳寿命。DomainPack 声明了材料力学约束（杨氏模量非负、损伤累积不可逆、Paris 定律适用范围）。

传统深度学习模型在已知合金上极准，但新配方是 OOD。工程师把微观结构图像输入系统。Core 的 HardGate 检测到当前状态域距离训练分布过远——模型没有该配方的校准数据，也没有有效的不确定性证书。模型被降权为 diagnostic_only。

Bridge 输出的不是“不建议使用该模型”——那是单一建议，Bridge 不输出。Bridge 输出的是：“当前状态：未知配方，OOD。可用行动：使用保守物理约束模型（Paris 定律，取已知最保守材料参数），给出安全寿命下限 Y。不可用：基于深度学习模型的精确寿命预测。有条件可用：若补充该配方的疲劳试验数据，重新校准模型，可申请链路升级。”

Hamiltonian 骨架在此作为监察员：即使深度学习模型被用于分析，其输出的能量耗散路径必须满足热力学约束。若模型预测的疲劳裂纹扩展路径违反了能量守恒，约束卡片直接拒绝输出。这不替代 DFT，不替代相场模拟，这是保证“数据驱动模型不在它不认识的领域产生非物理的自信错误”。

约束适用域的发现：

当新配方在极端温度下发生相变，材料科学家之前声明的约束卡片（如“损伤累积遵循 Paris 定律”）可能不再适用。Core 检测到约束验证器返回 not_applicable。该约束进入 suspended，系统标记“约束 C_X 在当前温度域不适用。建议审查适用域是否需要扩展或创建新约束卡片。”

Lab 在此时的价值：它可以在隔离环境中用仿真数据探索“如果 Paris 定律不成立，替代的损伤演化形式可能是什么”，生成候选约束假设（如“在 1200°C 以上，损伤遵循修正的 Kachanov 蠕变损伤律”），提交 Core 审查。

这套系统不是什么
不替代第一性原理计算（DFT），不替代疲劳试验机，不自动发明新材料。它是材料建模的安全守门员——在黑箱模型自信地错的时候阻止它误导工程师，在已知物理约束不再适用的时候检测到并标记，给材料科学家一个结构化的“无知报告”而非一个看似精确但危险的数字。

跨场景的共同模式
六个场景的不同，只在于知识边界的位置：

机器人：仿真与真实接触的边界

科研：已知物理与未知现象的边界

数据分析：正常老化的渐变与身份改变的边界

医疗：数据驱动预测与生理约束的边界

教育：不同数学骨架的适用域边界

新材料：已知合金的训练域与新配方的 OOD 边界

系统的统一行为不变：

知道什么可信（Core 的资格审判和约束验证）

知道有什么新可能（Lab 的隔离证据供应）

知道现在能做什么（Bridge 的结构化行动空间）

知道这一切是围绕什么的（TwinObjectModel 的统一孪生对象）

知道这个场景是什么（DomainPack 的配置实例化）

系统不做的：不替代物理仿真器、不替代控制器、不替代数据平台、不替代专业知识。它做的是这些工具和模型之间的信任治理。

追溯回最初的目标
最开始的描述是：“一个自适应的自我学习和进化的数字孪生基础设施，可以成为任何工业场景中可用的基础设施。”

其中“自适应”和“自我学习和进化”经历了最显著的收敛：

自适应现在体现为 Core 的链路权限动态调整和身份连续性管理——不是一个大系统自由进化，而是一个守门员根据约束和资格状态动态决定谁能在什么链路发言

自我学习和进化现在体现为 Lab 在隔离环境中持续生成候选模型和约束假设，提交 Core 逐级验证——进化在 sandbox 内自由，释放时被严格审查

“任何工业场景可用”现在体现为 DomainPack 的轻量级配置——不是修改 Core/Lab/Bridge，而是替换一个配置单元。领域专家从外部已有的知识库中引用模板，声明适用域和容差调整，半天内完成初稿。

终点不是最初设想的“模型动物园”或“物理世界操作系统”。终点是一个更诚实也更强的东西：一个知道自己在什么情况下会失效、知道如何帮助人在不确定中做出可审计决策的治理基础设施。
