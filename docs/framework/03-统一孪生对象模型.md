# 03-统一孪生对象模型

> **定位**: 核心数据模型与身份管理  
> **组件**: TOM (TwinObject Model)  
> **版本**: v0.3  
> **整合来源**: `TwinObjectModel v0.3.md`

---

## 1. 设计目标

TOM 的目标是建立 Polymorphic-Twin 中**所有实体**的统一表示方式。无论是用户、AI 代理、工具、文档、代码片段、知识节点，还是物理设备，都被建模为同一种数据结构——TwinObject。

设计原则：
1. **统一性**: 消除不同类型实体之间的表示差异
2. **可扩展性**: 支持任意属性的动态添加
3. **可投影性**: 同一对象在不同场景下呈现不同视图
4. **可溯源性**: 所有对象都有完整的身份谱系，支持来源追踪
5. **可组合性**: 对象之间可以灵活组合、引用、继承

## 2. TwinObject 结构

### 2.1 核心字段

```yaml
TwinObject:
  # === 身份层 (Identity) ===
  id: "uuid_or_uri"           # 全局唯一标识
  type: "object_type"         # 对象类型 (user | agent | tool | doc | code | knowledge | device | ...)
  version: "1.0.0"            # 对象 schema 版本
  
  # === 谱系层 (Lineage) ===
  lineage:
    creator_id: "uuid"        # 创建者
    created_at: "timestamp"
    provenance: []            # 来源链 [{source, method, timestamp}]
    parent_id: "uuid"         # 父对象（支持继承）
    fork_from: "uuid"         # 派生来源
  
  # === 结构层 (Structure) ===
  structure:
    schema_ref: "uri"         # 结构定义引用
    attributes: {}            # 属性字典 (任意键值)
    content: {}               # 内容载荷（类型特定）
    relationships: []         # 关系列表 [{target_id, type, strength, metadata}]
  
  # === 状态层 (State) ===
  state:
    lifecycle: "active"       # active | archived | deprecated | deleted
    health: "healthy"         # healthy | degraded | failing | unknown
    last_modified: "timestamp"
    access_stats: {}          # 访问统计
  
  # === 约束层 (Constraints) ===
  constraints:
    attached: []              # 附加的约束卡片 ID 列表
    inherited: []             # 继承的约束卡片 ID 列表
    overrides: {}             # 约束覆盖设置
  
  # === 意图层 (Intent) ===
  intent:
    current_goal: "string"
    pending_tasks: []
    preferences: {}           # 用户/代理偏好
  
  # === 视图层 (Views) ===
  views:
    default: "view_id"
    available: []             # 可用视图列表
    active_view: "view_id"    # 当前激活视图
```

### 2.2 内容载荷示例

不同类型的 TwinObject 有不同的 `content` 结构：

**用户 (user)**:
```yaml
content:
  profile: {name, email, avatar}
  credentials: {}       # 凭据（加密存储）
  settings: {}          # 个人设置
```

**AI 代理 (agent)**:
```yaml
content:
  model_config: {provider, model, parameters}
  capability_set: []    # 能力列表
  memory_snapshot: {}   # 记忆快照引用
  execution_log: []     # 执行日志
```

**文档 (doc)**:
```yaml
content:
  format: "markdown"
  body: "..."
  metadata: {title, tags, category}
  embeddings: {}        # 向量表示引用
```

**代码 (code)**:
```yaml
content:
  language: "python"
  source: "..."
  ast_ref: "uri"        # AST 表示引用
  dependencies: []
  test_refs: []         # 关联测试
```

**知识节点 (knowledge)**:
```yaml
content:
  concept: "概念名称"
  definition: "定义"
  relations: []         # 概念关系
  evidence: []          # 证据来源
  confidence: 0.95      # 置信度
```

### 2.3 关系定义

对象之间的关系是 TOM 的核心表达能力：

```yaml
Relationship:
  target_id: "uuid"         # 目标对象
  type: "relationship_type"  # 关系类型
  strength: 0.8             # 关系强度 [0, 1]
  bidirectional: false      # 是否双向
  metadata: {}              # 关系元数据
```

**预定义关系类型**:

| 关系类型 | 含义 | 示例 |
|----------|------|------|
| `owns` | 所有权 | 用户 owns 文档 |
| `created` | 创建关系 | 代理 created 代码 |
| `depends_on` | 依赖 | 代码 depends_on 库 |
| `references` | 引用 | 文档 references 知识节点 |
| `part_of` | 组成部分 | 段落 part_of 文档 |
| `version_of` | 版本关系 | v2 version_of v1 |
| `contradicts` | 矛盾 | 假设 A contradicts 假设 B |
| `supports` | 支持 | 证据 supports 结论 |
| `similar_to` | 相似 | 文档 similar_to 文档 |
| `triggers` | 触发 | 事件 triggers 任务 |

## 3. 视图投影 (View Projection)

### 3.1 视图定义

视图是 TwinObject 在特定场景下的投影，决定：
- 哪些属性可见
- 哪些关系可遍历
- 哪些操作可执行
- 以什么格式呈现

```yaml
View:
  id: "view_id"
  name: "视图名称"
  scope: "scene_id"         # 所属场景
  
  projection:
    include_attributes: []   # 包含的属性名列表（空表示全部）
    exclude_attributes: []   # 排除的属性名列表
    include_relations: []    # 包含的关系类型
    max_depth: 3             # 关系遍历最大深度
    
  transform:
    format: "json"           # 输出格式
    redact: []               # 脱敏字段
    localize: "zh-CN"        # 本地化
    
  permissions:
    readable_by: ["role1", "role2"]
    writable_by: ["owner"]
    executable_by: ["admin"]
```

### 3.2 视图示例

**同一代码对象的不同视图**:

```yaml
# 视图 1: 开发者视图
dev_view:
  include_attributes: ["content.source", "content.language", "content.dependencies"]
  include_relations: ["depends_on", "version_of"]
  format: "code_block"

# 视图 2: 管理者视图
manager_view:
  include_attributes: ["state.health", "state.access_stats", "intent.pending_tasks"]
  include_relations: ["created_by", "part_of"]
  format: "summary_card"
  redact: ["content.source"]   # 隐藏源代码

# 视图 3: AI 代理视图
agent_view:
  include_attributes: ["content.ast_ref", "content.test_refs", "relationships"]
  include_relations: ["depends_on", "references", "similar_to"]
  format: "structured_json"
```

### 3.3 视图解析流程

```
请求: 获取对象 O 在场景 S 下的视图
    ↓
1. 查找场景 S 对应的默认视图 V
    ↓
2. 检查请求者的角色是否在 V.permissions.readable_by 中
    ↓
3. 遍历对象 O 的属性，按 projection 规则过滤
    ↓
4. 遍历对象 O 的关系，按 projection 规则过滤和截断
    ↓
5. 应用 transform（格式转换、脱敏、本地化）
    ↓
6. 返回投影后的对象表示
```

## 4. 权限矩阵

### 4.1 基础权限模型

TOM 的权限基于**属性级**和**关系级**的细粒度控制：

```yaml
Permission:
  subject: "user_id or role"
  object: "object_id or pattern"
  action: "read | write | execute | delete | delegate"
  
  conditions:
    attribute: "state.lifecycle"
    operator: "equals"
    value: "active"
  
  scope: "global | scene_specific"
  priority: 100
```

### 4.2 权限解析规则

权限判定采用**显式拒绝优先**策略：

1. 收集所有匹配的权限规则（按 subject、object、action 匹配）
2. 如果有任何规则显式拒绝（deny），则最终结果为拒绝
3. 如果有允许规则且没有拒绝规则，则允许
4. 如果没有匹配规则，则采用默认策略（通常是拒绝）

### 4.3 继承与覆盖

权限支持继承和覆盖：

```
全局权限 (Global)
    ↓ 继承
场景权限 (Scene)
    ↓ 继承
对象权限 (Object)
    ↓ 继承
属性权限 (Attribute)

每一层都可以:
  - 继承上层权限
  - 添加上层没有的权限
  - 覆盖上层的权限（提高或降低）
  - 显式拒绝上层的权限
```

## 5. 身份谱系 (Identity Lineage)

### 5.1 谱系结构

身份谱系记录对象的完整来源链，用于溯源、权限继承和信任计算：

```yaml
Lineage:
  creator_id: "uuid"           # 直接创建者
  created_at: "timestamp"
  
  provenance:                  # 来源链（从最近到最远）
    - source: "user_A"
      method: "manual_create"
      timestamp: "2026-01-01T00:00:00Z"
    - source: "agent_B"
      method: "auto_generate"
      timestamp: "2026-01-01T00:00:01Z"
      parent_of: "previous"
    - source: "template_C"
      method: "template_instantiation"
      timestamp: "2026-01-01T00:00:02Z"
      
  parent_id: "uuid"            # 父对象（结构继承）
  fork_from: "uuid"            # 派生来源（内容复制）
  merge_from: ["uuid1", "uuid2"]  # 合并来源
```

### 5.2 谱系应用场景

**溯源**:
```
问题: "这段代码是谁生成的？"
查询: 代码对象 → lineage.provenance
结果: "用户 A 通过 Agent B 使用模板 C 生成"
```

**信任继承**:
```
规则: 子对象信任度 ≤ 父对象信任度 × 衰减系数
应用: 从模板生成的对象继承模板的信任度，但按比例衰减
```

**责任归属**:
```
场景: AI 生成的内容出现错误
追踪: 内容对象 → lineage → 确定最终责任方
        - 若用户明确确认: 用户承担责任
        - 若系统自主生成: 系统运营方承担责任
```

### 5.3 谱系可视化

```
[模板 C] ──template_instantiate──► [Agent B 配置]
                                       │
                                       ▼
[用户 A] ──────委托执行────────────► [Agent B 运行]
                                       │
                                       ▼
                                   [输出对象 O]
                                   
谱系链: O ← Agent B ← 用户 A
       O ← 模板 C
```

## 6. 对象生命周期

### 6.1 状态机

```
         ┌──────────────┐
         │   creating   │
         └──────┬───────┘
                ▼
         ┌──────────────┐
    ┌───►│    active    │◄────┐
    │    └──────┬───────┘     │
    │           │              │
    │           ▼              │
    │    ┌──────────────┐      │
    │    │  deprecated  │      │
    │    └──────┬───────┘      │
    │           │              │
    │           ▼              │
    │    ┌──────────────┐      │
    └────┤   archived   ├──────┘
         └──────┬───────┘
                ▼
         ┌──────────────┐
         │   deleted    │
         └──────────────┘
```

### 6.2 状态转换规则

| 转换 | 触发条件 | 副作用 |
|------|----------|--------|
| creating → active | 初始化完成，通过基本验证 | 通知订阅者 |
| active → deprecated | 存在更好的替代版本 | 更新引用指向新版本 |
| active → archived | 长期未使用，或场景下线 | 保留但不可修改 |
| deprecated → active | 回滚到旧版本 | 恢复引用 |
| archived → active | 重新激活 | 恢复可修改状态 |
| any → deleted | 明确删除请求 + 权限验证 | 级联删除或解除引用 |

## 7. 与相邻组件的交互

### 7.1 TOM ↔ Core

- TOM 为 Core 提供对象元数据和结构信息
- Core 通过 TOM 的视图投影获取对象可见属性
- Core 的链路权限计算依赖 TOM 的身份谱系

### 7.2 TOM ↔ Lab

- Lab 将探索发现的新对象注册到 TOM
- Lab 使用 TOM 的关系网络进行模式发现
- Lab 的探索结果以 TwinObject 形式存储

### 7.3 TOM ↔ Bridge

- Bridge 通过 TOM 查找行动所需的对象
- Bridge 的执行结果更新 TOM 中对象的状态
- Bridge 创建的新对象（如计划、日志）注册到 TOM

### 7.4 TOM ↔ DP

- DomainPack 定义场景中对象的 schema 和默认视图
- TOM 根据当前激活的 DomainPack 调整对象的呈现方式
- 场景切换时，TOM 重新计算所有相关对象的视图投影
