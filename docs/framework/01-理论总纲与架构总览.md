## 1. 项目定位

### 1.1 一句话定义

**Polymorphic-Twin（多态孪生）** 是一个面向复杂认知任务的智能体框架，通过"统一孪生对象模型 + 场景化配置 + 可证伪约束治理 + 探索-决策双引擎"的四层架构，实现 AI 系统从"单一功能调用"到"自主目标达成"的跃迁。

### 1.2 核心问题域

传统 AI 系统面临的核心矛盾：
- **能力碎片化**: 每个模型/工具只解决单点问题，无法串联成完整任务流
- **上下文丢失**: 多轮交互中历史信息、约束条件、用户偏好不断衰减
- **不可控探索**: Agent 自由度过高时行为不可预测，过低时丧失自主性
- **场景隔离**: 不同场景（编程、科研、创作）需要完全不同的工作流，无法复用底层能力

Polymorphic-Twin 的解决思路：**将"任务执行"重新定义为"对象演化"** —— 所有参与者（用户、AI、工具、环境）都被建模为统一孪生对象（TwinObject），在受约束的场景空间中自主探索、协作决策、持续演化。

### 1.3 设计哲学

| 原则 | 含义 |
|------|------|
| **可证伪性优先** | 任何约束、假设、结论都必须可以被证伪或验证，拒绝黑箱操作 |
| **对象即上下文** | TwinObject 同时承载数据、状态、约束、意图，消除传统"上下文窗口"概念 |
| **场景即边界** | DomainPack 定义明确的场景边界，在边界内给予最大自由度 |
| **探索与决策分离** | Lab 负责无约束探索，Bridge 负责带约束决策，两者通过资格函数桥接 |
| **可组合大于可配置** | 优先通过对象组合而非参数配置来适配不同场景 |

### 2.2 五组件职责

| 组件 | 版本 | 核心职责 | 输入 | 输出 |
|------|------|----------|------|------|
| **Core** | v1.3 | 约束治理、资格验证、安全回落 | 约束声明 + 对象状态 | 资格判定 + 治理报告 |
| **Lab** | v0.4 | 无约束探索、假设生成、模式发现 | 问题/目标 + 场景配置 | 假设集 + 探索路径 |
| **Bridge** | v0.3 | 带约束决策、行动编排、审计追踪 | Lab 输出 + Core 约束 | 可执行计划 + 审计日志 |
| **TOM** | v0.3 | 统一数据模型、身份管理、视图投影 | 任意实体描述 | 结构化 TwinObject |
| **DP** | v0.3 | 场景边界定义、配置管理、生命周期 | 场景需求 | DomainPack 配置 |

### 2.3 五个闭环

系统运行由五个相互嵌套的闭环驱动：

1. **感知闭环 (Perception Loop)**
   - 外部输入 → TOM 对象化 → 视图投影 → 场景匹配
   - 周期: 实时

2. **探索闭环 (Exploration Loop)**
   - 场景激活 → Lab 假设生成 → 模式发现 → 假设排序
   - 周期: 按需触发

3. **决策闭环 (Decision Loop)**
   - 候选假设 → Core 资格验证 → Bridge 行动编排 → 执行计划
   - 周期: 每次探索后

4. **执行闭环 (Execution Loop)**
   - 计划分发 → 工具调用 → 结果回收 → 状态更新
   - 周期: 实时

5. **演化闭环 (Evolution Loop)**
   - 执行结果 → 约束学习 → 场景更新 → 对象谱系演化
   - 周期: 长期累积

## 3. 关键概念速查

| 概念 | 定义 | 所属组件 |
|------|------|----------|
| **TwinObject** | 系统中所有实体的统一表示，包含结构、状态、约束、意图 | TOM |
| **视图 (View)** | TwinObject 在特定场景下的投影，决定可见属性与行为 | TOM |
| **DomainPack** | 场景配置单元，定义场景边界、角色、约束、工具集 | DP |
| **资格函数 Q** | 判定某对象/行为是否满足特定约束的函数，返回 [0,1] | Core |
| **安全回落 (Fallback)** | 当主路径失败时，按预设层级降级执行的机制 | Core |
| **链路权限** | 跨对象交互时的动态权限计算，基于身份谱系和场景角色 | Core |
| **探索空间 (Lab Space)** | Lab 中无约束的假设生成空间，所有想法均可被表达 | Lab |
| **行动空间 (Action Space)** | Bridge 中受约束的可执行行动集合，经 Core 验证 | Bridge |
| **约束卡片** | Core 中约束的结构化表示，包含触发条件、判定逻辑、回落策略 | Core |
| **身份谱系** | TwinObject 的身份来源链，用于权限继承和溯源 | TOM |

## 4. 与外部系统的关系

```
Polymorphic-Twin
├── 上游输入
│   ├── 用户自然语言需求
│   ├── 外部 API / 数据源
│   ├── 知识库 (向量/图/文档)
│   └── 物理传感器 / IoT 数据
│
├── 下游输出
│   ├── 可执行计划 (调用外部工具)
│   ├── 结构化报告 / 分析结果
│   ├── 更新后的知识库
│   └── 审计日志 / 追踪数据
│
├── 横向集成
│   ├── LLM Provider (OpenAI / Anthropic / 本地模型)
│   ├── 工具生态 (代码执行、搜索、数据库)
│   └── 其他 Agent / 多 Agent 系统
```
