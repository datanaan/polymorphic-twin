# 06-生态接口规范

> **定位**: 统一对外交互契约  
> **版本**: API v1.1（为主），v1.0 演进差异见附录  
> **整合来源**: `Polymorphic-Twin 生态接口规范 v1.1.md` + `Polymorphic-Twin 生态接口规范 v1.0.md`

---

## 1. 设计目标

生态接口层是 Polymorphic-Twin 与外部世界（用户、其他系统、工具、数据源）交互的统一契约。其设计目标是：

1. **统一入口**: 无论外部系统使用什么协议（HTTP、gRPC、WebSocket、本地调用），都通过统一的接口语义交互
2. **视图投影**: 外部系统只能看到它们被授权看到的内容（通过 TOM 的视图投影）
3. **快照机制**: 支持系统状态的快照和恢复，便于调试和复盘
4. **适配器注册**: 外部系统可以通过适配器注册到 Polymorphic-Twin 生态中
5. **可观测性**: 所有交互都被记录，支持追踪和分析

## 2. 调用矩阵

### 2.1 接口分类

| 类别 | 说明 | 典型调用方 |
|------|------|-----------|
| **核心接口 (Core API)** | 约束治理、资格验证、权限查询 | 内部组件、管理工具 |
| **探索接口 (Lab API)** | 假设生成、模式发现、实验执行 | 研究工具、分析系统 |
| **决策接口 (Bridge API)** | 行动编排、计划执行、审计查询 | 执行引擎、自动化工具 |
| **对象接口 (TOM API)** | 对象 CRUD、视图投影、关系查询 | 所有外部系统 |
| **场景接口 (DP API)** | 场景切换、配置管理、工作流触发 | 应用层、管理系统 |
| **管理接口 (Admin API)** | 系统监控、配置管理、日志查询 | 运维工具、管理后台 |

### 2.2 接口概览表

| 接口 | 方法 | 路径 | 说明 |
|------|------|------|------|
| 约束验证 | POST | `/v1/core/validate` | 验证对象/行为是否满足约束 |
| 资格查询 | GET | `/v1/core/qualify` | 查询资格函数 Q 的结果 |
| 权限检查 | POST | `/v1/core/permission` | 检查链路权限 |
| 假设生成 | POST | `/v1/lab/hypothesize` | 生成假设集 |
| 模式发现 | POST | `/v1/lab/discover` | 发现数据模式 |
| 实验执行 | POST | `/v1/lab/experiment` | 执行实验计划 |
| 行动编排 | POST | `/v1/bridge/orchestrate` | 编排行动计划 |
| 计划执行 | POST | `/v1/bridge/execute` | 执行计划 |
| 审计查询 | GET | `/v1/bridge/audit` | 查询审计日志 |
| 对象创建 | POST | `/v1/tom/objects` | 创建 TwinObject |
| 对象查询 | GET | `/v1/tom/objects/{id}` | 查询对象 |
| 对象更新 | PUT | `/v1/tom/objects/{id}` | 更新对象 |

| 场景配置 | GET | `/v1/dp/config` | 获取场景配置 |
| 工作流触发 | POST | `/v1/dp/workflow` | 触发场景工作流 |
| 系统状态 | GET | `/v1/admin/status` | 查询系统状态 |
| 快照创建 | POST | `/v1/admin/snapshot` | 创建系统快照 |
| 快照恢复 | POST | `/v1/admin/restore` | 从快照恢复 |

## 3. 核心接口 (Core API)

### 3.1 约束验证

```http
POST /v1/core/validate
Content-Type: application/json

{
  "object": {
    "id": "obj_001",
    "type": "code",
    "content": {
      "source": "import os; os.system('rm -rf /')"
    }
  },
  "constraints": ["security_001", "security_002"],
  "context": {
    "scene_id": "secure_python",
    "actor_id": "user_001"
  }
}
```

**响应**:
```json
{
  "result": "fail",
  "violations": [
    {
      "constraint_id": "security_001",
      "constraint_name": "禁止危险系统调用",
      "level": "hard",
      "detail": "检测到 os.system 调用，参数包含危险命令",
      "location": "line 1, column 18"
    }
  ],
  "fallback": {
    "available": true,
    "strategy": "block_and_report",
    "alternatives": ["使用 pathlib 替代", "请求人工审核"]
  }
}
```

### 3.2 资格查询

```http
GET /v1/core/qualify?object_id=obj_001&constraint_id=perf_001&context_scene=python_dev
```

**响应**:
```json
{
  "object_id": "obj_001",
  "constraint_id": "perf_001",
  "score": 0.85,
  "result": "partial",
  "explanation": {
    "checks": [
      {
        "item": "时间复杂度",
        "status": "pass",
        "detail": "O(n)，满足要求"
      },
      {
        "item": "空间复杂度",
        "status": "partial",
        "detail": "O(n^2)，超出预期，建议使用滚动数组优化"
      }
    ],
    "path": "约束卡片 perf_001 → 复杂度分析 → 空间复杂度检查"
  }
}
```

### 3.3 权限检查

```http
  "action": "write",

```

**响应**:
```json
{
  "granted": true,
  "level": "full",
  "factors": {
    "base_permission": 1.0,

    "emergency_factor": 1.0

}
```

## 5. 决策接口 (Bridge API)

### 5.1 行动编排

```http
POST /v1/bridge/orchestrate
Content-Type: application/json

{
  "goal": "部署优化后的查询到生产环境",
  "hypotheses": ["hyp_001"],
  "constraints": ["deploy_001", "rollback_001"],
  "preferences": {
    "downtime": "zero",
    "rollback_time": "< 30s"
  }
}
```

**响应**:
```json
{
  "plan": {
    "id": "plan_001",
    "steps": [
      {
        "id": "step_1",
        "action": "backup_index",
        "parameters": {"table": "orders", "index": "idx_old"},
        "depends_on": []
      },
      {
        "id": "step_2",
        "action": "create_index",
        "parameters": {"table": "orders", "index": "idx_new", "columns": ["user_id", "created_at"]},
        "depends_on": ["step_1"]
      },
      {
        "id": "step_3",
        "action": "verify_index",
        "parameters": {"index": "idx_new", "query": "..."},
        "depends_on": ["step_2"]
      },
      {
        "id": "step_4",
        "action": "switch_index",
        "parameters": {"from": "idx_old", "to": "idx_new"},
        "depends_on": ["step_3"]
```

## 9. 错误码规范

### 9.1 错误码定义

| 错误码 | 含义 | HTTP 状态码 | 说明 |
|--------|------|-------------|------|
| `E0001` | 约束验证失败 | 400 | 对象不满足约束条件 |
| `E0002` | 资格不足 | 403 | Q 函数返回不满足阈值 |
| `E0003` | 权限拒绝 | 403 | 链路权限计算结果为拒绝 |
| `E0004` | 对象不存在 | 404 | 请求的 TwinObject 不存在 |
| `E0005` | 视图不存在 | 404 | 请求的视图不存在 |
| `E0006` | 场景不存在 | 404 | 请求的 DomainPack 不存在 |
| `E0007` | 行动不可执行 | 422 | 环境不满足行动执行条件 |
| `E0008` | 回滚失败 | 500 | 回滚操作执行失败 |
| `E0009` | 探索超时 | 504 | Lab 探索超过最大时间限制 |
| `E0010` | 计划执行失败 | 500 | Bridge 计划执行失败 |
| `E0011` | 快照创建失败 | 500 | 系统快照创建失败 |
| `E0012` | 快照恢复失败 | 500 | 系统快照恢复失败 |

### 9.2 错误响应格式

```json
{
  "error": {
    "code": "E0001",
    "message": "约束验证失败",
    "detail": {
      "constraint_id": "security_001",
      "constraint_name": "禁止危险系统调用",
      "violation": "检测到 os.system 调用"
    },
    "request_id": "req_001",
    "timestamp": "2026-01-01T12:00:00Z"
  }
}
```

## 10. 适配器注册

外部系统可以通过适配器注册到 Polymorphic-Twin 生态中：

```http
POST /v1/admin/adapters
Content-Type: application/json

{
  "name": "GitHub Integration",
  "type": "repository",
  "protocol": "https",
  "endpoint": "https://api.github.com",
  "authentication": {
    "type": "oauth2",
    "client_id": "...",
    "scope": ["repo", "read:user"]
  },
  "capabilities": ["read_repo", "create_pr", "read_issues"],
  "mapping": {
    "repo": "TwinObject.type:repository",
    "issue": "TwinObject.type:ticket"
  }
}
```

## 11. 附录：v1.0 → v1.1 演进差异

| 变更项 | v1.0 | v1.1 |
|--------|------|------|
| 视图投影 | 仅支持默认视图 | 支持多视图切换和场景绑定 |
| 快照机制 | 仅支持全量快照 | 支持增量快照和选择性快照 |
| 适配器注册 | 需手动配置 | 支持动态注册和自动发现 |
| 错误码 | 10 个错误码 | 12 个错误码，增加 E0011/E0012 |
| 审计接口 | 无独立审计接口 | 新增 `/v1/bridge/audit` |
| 实验接口 | 实验结果同步返回 | 支持异步实验和进度查询 |
| 场景切换 | 无上下文保留选项 | 增加 `context_preservation` 参数 |
